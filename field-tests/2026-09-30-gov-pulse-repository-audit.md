# Gov Pulse repository audit

This is a read-only, maintainer-led Cave Pony audit of [gov-pulse](https://github.com/wilfgrainger/gov-pulse) at [`110d1bcf8943e29910e2dd943b332c270414b70d`](https://github.com/wilfgrainger/gov-pulse/commit/110d1bcf8943e29910e2dd943b332c270414b70d) on 30 September 2026. It covers the evidence pipeline, public application, accessibility, and release path. It is an **unpaired field use**, not independent-user evidence or a performance comparison.

## Task and environment

The user asked: “We could use CavePony to review the gov-pulse... and use that as our example?” They then corrected the scope: “cancel - be broader.... entire repo - not this uscase”. The target became a repository-wide audit rather than a single migration-card change. Gov-pulse was kept unchanged.

## Findings, ranked by consequence

### 1. High — valid government-contracts data can be filtered from the live publication

[`buildGovernmentContractsPayload`](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/contracts/government-contracts.js#L300-L312) writes `__observation.maxAgeHours: 72`. The [live merge](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/worker/publication-entry.js#L91-L119) attaches the section to the national snapshot, but the shared [currentness check](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/worker/publication-currentness.js#L107-L115) requires a positive integer `maxAgeDays`. The [queue publication](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/worker/queued-publication-entry.js#L248-L257) filters the merged section before delivery.

A read-only probe used the complete, valid 100-award contract fixture, called the real payload builder and merge, then checked currentness and filtering. It returned `strict payload valid true`, `reason: invalid-observation-policy`, and `survives national filter false`. The section can be collected successfully yet omitted from the public national snapshot. **Smallest correction:** add `maxAgeDays: 3` for shared currentness while retaining `maxAgeHours: 72` for the existing [strict contracts checker](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/contracts/government-contracts.js#L315-L332), then add one live merge/filter regression check. This preserves the 72-hour policy and the seed/merge caller. This proves the code path, not the observed production response.

### 2. Medium — PRs deleting code can take the docs-only validation lane

The [classifier](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/scripts/classify-pr-validation.mjs#L9-L25) uses `git diff --diff-filter=ACMR`, omitting deleted files. The [workflow](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/.github/workflows/pr-validation.yml#L40-L103) skips lint, unit tests and build for a docs lane. An isolated Git fixture deleted `app/runtime.ts` and edited `README.md`; `git diff --name-status` showed both, while the classifier printed `Lane: docs` and only `README.md`. **Smallest correction:** include `D` in the classifier's diff filter and test a mixed deletion/documentation PR. The main-branch deployment has its own test gate, but PR review loses its code checks.

### 3. Medium — international comparison can outlive its last successful check indefinitely

The [seven-day `due` guard](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/worker/international-comparison-publication.js#L290-L306) schedules a refresh; the public KV read validates the schema without limiting the age of `checkedAt`. A [refresh with no available measures](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/worker/international-comparison-publication.js#L309-L345) retains the prior record. The [public route](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/worker/public-data-entry.js#L265-L276) keeps serving it.

A read-only handler probe put a schema-valid record checked on **1 August 2026** into fake KV and requested the route on **30 September 2026**. It returned HTTP 200 with the old value and check date. **Smallest correction:** choose an editorial maximum age for public delivery, fail closed after it, and show the last check date while valid. Seven days is a refresh interval, not necessarily the right expiry. The probe did not query production KV.

### 4. Medium — an open homepage can keep expired figures marked “Current”

The server filters evidence at request time, but [`NationalEvidenceEdition`](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/app/components/NationalEvidenceEdition.tsx#L140-L155) derives client state once and performs only one mount-time fetch. It does not revisit expiry while a tab remains open. A boundary probe showed `sectionCurrentness` changing from current at 11:59:59 to `explicit-expiry` at 12:00:00; the mounted lead, cards and counts have no timer to reflect that change. The [explorer](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/app/components/DataExplorer.tsx#L247-L268) already reevaluates on a clock. **Smallest correction:** recheck the held snapshot against currentness periodically, and refresh it when possible. This affects long-lived tabs; initial page rendering uses the currentness filter.

## Appendix — further observations and decisions

- **Prepared health versus public delivery:** a prepared artifact's deadline includes optional four-hour betting evidence. When it expires, the snapshot route can filter that optional section and serve a current, ready national publication through KV fallback, while [health](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/worker/public-data-entry.js#L279-L293) reports `bootstrapping`, `ready:false` because it checks only the prepared artifact. A fixture probe observed snapshot HTTP 200 ready and health HTTP 200 bootstrapping. Health is documented as a prepared-publication signal, so this is a status-semantics question to resolve rather than proof of stale public data.
- **Bootstrap recovery timing:** a deterministic mock finalized the first run just after the four-minute recovery threshold. The [bootstrap script](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/scripts/bootstrap-cloudflare-publication.mjs#L331-L354) then watched only the second attempt and timed out despite the first run's valid degraded finalization. Check every dispatched attempt's terminal state before treating recovery as failed. This was a mock timing result, not a production run.
- **RSS and keyboard route coverage:** [`feed.xml`](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/app/feed.xml/route.ts#L7-L8) is deliberately static, although its title promises latest verified evidence and the Worker can publish without a web build. Either tie feed updates to publication or describe it as a build-edition feed. Home and explorer have skip links; [topic pages](https://github.com/wilfgrainger/gov-pulse/blob/110d1bcf8943e29910e2dd943b332c270414b70d/app/section/%5Bid%5D/page.tsx#L84-L99), sources and trust routes do not. A shared skip link would avoid repeated keyboard traversal of the navigation.
- **Release smoke:** it explicitly allows degraded evidence so a source outage does not block a code release. The current probe also accepts `bootstrapping` when no snapshot is available; a manual dispatch can skip evidence bootstrap. Decide whether code-only success should be labelled separately from reader data readiness. The audit did not recommend turning every external source failure into a deployment blocker.

The review found no reason for a wholesale framework change or a blanket reduction in tests. Its fixes are local: one unit mismatch, one PR classifier option, explicit publication age, and a client currentness clock. Other inspected paths—source-specific parsing, HTTPS/response limits, queue finalization, section download gating, separate crime measures, Cloudflare route scoping, and no-JavaScript content visibility—produced no additional material finding in this pass.

## Proof and verdict

At the pinned gov-pulse commit, `npm test` passed **472 tests in 96 files** (including the hosting boundary check), `npm run lint` passed, and `npm run build:check` completed. The local Node/npm versions were 24.19.0/11.9.0 rather than the repository's required 24.17.0/11.13.0; install emitted engine warnings. The [exact-head GitHub push workflow](https://github.com/wilfgrainger/gov-pulse/actions/runs/36615792174) reported success. `git status --short` was empty after the audit. Focused read-only probes above demonstrate conditions the passing suite does not cover.

The audit changed **no gov-pulse files**. It did not inspect live Cloudflare state, source responses, production browser behavior, dependency vulnerabilities, or every repository line. There was no equivalent baseline run without Cave Pony or blinded reviewer. The finding quality is inspectable, but its causal or comparative advantage is **inconclusive**; this record does not satisfy the independent-user or authenticated installed-host behavior gates for v1.0.0.
